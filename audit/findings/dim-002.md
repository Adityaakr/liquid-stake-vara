# DIM-002: `bufferBps` has two incompatible definitions behind one field (gear adapter vs mock adapter)

**Severity:** LOW
**Type:** semantic_mismatch (Trap 6: same name, different quantity; both are `D4{1}` but ratios of different things)
**Location:** `/Users/adityakrx/liquid-stake/src/chain/gearAdapter.ts:397`
**Related:** `/Users/adityakrx/liquid-stake/src/chain/mockAdapter.ts:114` (`bufferBps: 720n`), `/Users/adityakrx/liquid-stake/src/chain/types.ts` (`ProtocolStats.bufferBps`)

## Code

```ts
// src/chain/gearAdapter.ts:397
bufferBps: pool.staked > 0n ? (pool.reserve * 10_000n) / pool.staked : 0n,
//          D12{VARA} * D4 / D12{VARA} = D4{1}   — dimensionally fine
```

where `pool.staked = info.total_assets` (= `distributable`) and `pool.reserve = info.reserve`.

## Analysis

On chain, `reserve = distributable + fees_accrued + unbonding_total + locked_rewards`
(`programs/vara-pool/app/src/lib.rs:230`), so `reserve >= total_assets` always and the gear adapter's
`bufferBps` is **≥ 10 000 bps (≥ 100 %)**. It is a "reserve-to-liabilities" ratio, not a buffer.

The mock adapter publishes `bufferBps: 720n`, i.e. a 7.2 % liquidity buffer *on top of* the stake, which
is what the field name says. The two adapters therefore disagree by construction:

| Pool state | gear adapter | mock adapter |
|------------|--------------|--------------|
| 1 000 VARA staked, 0.67 VARA tranche just funded, no fees | `(1000.67e12 * 1e4) / 1000e12` = **10 006 bps** | 720 bps |
| 1 000 VARA staked, 100 VARA unbonding, 10 VARA fees | (1 000 + 100 + 10) / 1 000 → **11 100 bps** | 720 bps |

The formula that matches the mock's meaning is `(reserve - total_assets) * 10_000 / total_assets`
(= fees + unbonds + locked rewards over what holders own), which would give 6 bps and 1 100 bps in the two
rows above.

## Impact

Currently informational: no page reads `ProtocolStats.bufferBps` (grep over `src/app` and `src/ui` finds no
consumer). If a UI element is wired to it later, it will render "buffer 100.06 %" on chain versus "7.2 %" in
the simulation, and any threshold logic written against the mock (e.g. "warn below 500 bps") will never fire
on chain.

## Recommendation

Pick one definition and document it in `types.ts`. If the intent is "liquidity available beyond what holders
are owed":

```ts
bufferBps: pool.staked > 0n ? ((pool.reserve - pool.staked) * 10_000n) / pool.staked : 0n,
//          (D12{VARA} - D12{VARA}) * D4 / D12{VARA} = D4{1}
```

and update the `ProtocolStats.bufferBps` doc comment to say which ratio it is. If the reserve-to-liabilities
ratio is wanted instead, rename the field (e.g. `reserveRatioBps`) and change the mock to `10_720n`.
